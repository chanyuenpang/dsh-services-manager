# 安装与回滚

宿主：Windows + DSH 0.2 Desktop 或独立 Web profile，Node >=20。插件包含宿主、客户端及 `dsh-services` CLI。
**挂入正式 profile 前，必须用隔离 DSH_HOME、新 profile、独立端口完成真实启动门禁。正式重启需用户对本次明确授权。** 安装包与 CLI 验证不能代替门禁。

## 离线包与入口（不需要源码）

维护者执行 `npm pack` 交付 tarball；保留 `private:true`，不发布 registry。接收者持有包即可在全新目录离线安装 CLI：

```powershell
# 换成实际收到的包路径；目录可包含空格
npm install --offline --ignore-scripts --legacy-peer-deps --no-audit --no-fund C:/Packages/dsh-services-manager-0.2.2.tgz
& ./node_modules/.bin/dsh-services.cmd --help
node ./node_modules/dsh-services-manager/src/cli.mjs --help
```

CLI 本身不需要 Cordis，故独立安装跳过 peer 自动解析；插件运行所需 Cordis peer 由 DSH 宿主提供。此命令只安装 CLI 包，**不会挂载插件或启动宿主**。

已装进 profile 时，用 `<profile>/node_modules/.bin/dsh-services.cmd` 或 `node <profile>/node_modules/dsh-services-manager/src/cli.mjs`。PATH 不一定有 bin；`--help` 会打印绝对入口。它是 agent 的主要自足说明，不注入 skill，不要求仓库或另行下载版本。

CLI 由显式 `--url` / `DSH_SERVICES_URL` 选择正在运行的 loopback 宿主。用户从其授权的访问 URL 提供 token，经环境变量 `DSH_SERVICES_TOKEN` 或 `--token-stdin` 输入；不能放到 argv、共享聊天或日志。token→cookie→/dsh-services，禁止跨地址重定向；不探测其他 profile/token、不裸开放接口。该认证具有现有宿主权限，**不是 agent 权限沙箱**。详细字段、JSON/stdin 示例、退出码、revision 恢复与持久语义均在离线帮助中。

## 安装进目标 profile

```powershell
# 必须先通过下文沙箱门禁；路径是示例，换成收到的 tarball
# DSH 自己处理 profile 依赖与 dsh.profile.bundles
# DSH 0.2 Desktop（推荐）
dsh plugin --profile desktop add C:/Packages/dsh-services-manager-0.2.2.tgz
# 独立 Web profile：将 desktop 换成 web
```

检查目标 `<DSH_HOME>/profiles/<profile>/package.json`：依赖有 dsh-services-manager，dsh.profile.bundles 包含包名。不要假定 node_modules 指向开发仓库；tarball 安装必须能在没有源码时使用。

此版本要求 DSH >=0.2.2-rc.1 / Cordis >=4.1。插件自行注入 `subprocess`、`connection`、`webServer`；包内 patch 给 Connection 补 `webServer` 并保留当前模板的 `webStartup`，不再使用旧 `webRuntime`。不需要手改目标 profile 的 connection 行。

在 GUI 中由 `plugin_manager` 安装、维护 profile，勿手工编辑其依赖或 patch。新装可能即时激活，升级已有包可能返回 restart-required；以安装结果为准。正式重启另需单次授权，不能因安装而自动执行。

开发者可将自己的工作树绝对路径传给 `dsh plugin ... add` 进行 link 安装。历史示例 `G:/Projects/dsh-plugins/dsh-services-manager`、mechanics/tiny-world 路径仅是开发者本机目录，**不是发行包默认值或用户安装前提**。

## 安装后验证

1. 设置页出现「服务管理」，认证首页客户端模块清单含 dsh-services-manager。
2. 内置 `dsh` 条目是当前实例、managed=false；新装无其它服务定义。
3. `<DSH_HOME>/.dsh-services-manager/services.json` 只在不存在时创建空列表，旧用户文件不覆盖，不迁移成空配置。升级前建议备份。
4. 已登记服务按真实端口 LISTENING 显示活性，所有权 spawned/discovered 不混淆；不要期待机器预先有 mechanics/tiny-world。
5. 无源码 CLI `--help` 可从任意 cwd 使用；在授权沙箱上经 register/list/start/stop 验证实际认证传输。

启停先保存意图再执行；start=true，stop=false，restart 不改。执行失败查看 policyCommitted/autostart/configRevision，不把失败误当成未写入。删除只删定义，不停止进程。坏条目会阻止登记/删除/策略变更，须先修复。CONFIG_CONFLICT 后 get 读回，核对后用新 revision 提交，不自动覆盖。

## 沙箱门禁（开发/上线前，不动正式环境）

```powershell
# 使用你选定的隔离目录，绝不能指向真实 DSH_HOME
$env:DSH_HOME = 'C:/Temp/dsm-isolated-home'
New-Item -ItemType Directory -Force $env:DSH_HOME | Out-Null
dsh --profile sandbox --from-default-profile web --dump-config
# 包内 patch 已补 connection 注入，无需手改 profile
dsh plugin --profile sandbox add C:/Packages/dsh-services-manager-0.2.2.tgz
dsh --profile sandbox --port 3099 --no-open
```

必须同时有：插件已加载日志；无 plugin tree/inject 错误；独立端口监听；用本实例授权 URL 验证首页客户端模块清单。完成后只停止此沙箱进程，不长期占端口。

**绝不要在沙箱调用 restart-supervisor/restart-dsh**：其清扫按 DSH 安装识别，可能杀正式实例。恢复测试用普通退出/重新启动沙箱。CLI 不暴露这些入口。

## 回滚

先备份 services.json，必要时在仍运行的插件里 stop 自己登记的服务（这会保存 false）。移除插件不是停服务承诺，尤其外部服务/autoStopOnExit=false 项不会因移除自动停止。

```powershell
dsh plugin --profile desktop remove dsh-services-manager
# 独立 Web profile：将 desktop 换成 web
# 用户授权本次重启后，新进程不再加载面板/宿主
# 独立 CLI 安装目录可 npm uninstall dsh-services-manager
```

升级回退可安装上一份 tarball，保留 services.json。通常不要删除 `<DSH_HOME>/.dsh-services-manager`；它含用户定义与日志。确需删除须确认备份与数据丢失影响。仅删定义不会终止正在运行的进程。

## 故障排查与日志

| 现象 | 处理 |
| --- | --- |
| CLI 不在 PATH | 用 profile 的 .bin 或帮助打印的 node 绝对入口 |
| CLI 无法连接/未认证 | 核对用户明确选择的 URL、运行实例、token；不扫描或猜测其它宿主 |
| CONFIG_CONFLICT / 退出 5 | get 读回定义/revision，审阅后重提同一稳定 id |
| PORT_OWNED_BY_OTHER | 先核对实际进程，再修复正确签名；不能 force 绕过安全校验 |
| 设置页缺分区 | 检查依赖、bundles、模块清单与插件加载日志；宿主改动需新进程 |
| profile 树起不来 | 核对 DSH 版本、插件自己的 webServer 注入；apply 必须使用第二个 config 参数 |

日志目录 `<DSH_HOME>/.dsh-services-manager/logs`：host-restart.log 是宿主重启记录；dsh-web.log 只用于看守重启的独立 Web 实例（可能含 token，需保护），Desktop 由应用自身管理输出。服务行日志来自插件托管输出，重建 manager 后旧内存日志不保留。

## 本次验证的边界

`npm test` 和 `npm run verify-cli-package` 覆盖单测、tarball 离线新目录安装、含空格路径/非仓库 cwd 的 bin 与直接入口、隔离认证 HTTP 客户端；HTTP 测试服务不是 DSH 真实认证中间件。真实 DSH 沙箱门禁必须另行执行，不能声称这些测试已授权正式挂载/重启。
