# 安装与回滚

本插件是**可安装的 DSH Web 插件**：一个 npm 包 + profile composition 里的一个 bundle 行。
宿主：Windows + `dsh web`。

> 流程铁律：**任何挂进正式 profile 的动作，都必须先在隔离沙箱里通过一次真实启动测试**（见仓库根 `AGENTS.md`）。

## 安装

```powershell
# 1) 装进目标 profile（本机开发用 link:，改源码后重启即生效）
dsh plugin --profile web add G:/Projects/dsh-plugins/dsh-services-manager

# 2) 确认 profile 的两处都改到了（第 1 步会同时做这两件事）
#    <DSH_HOME>\profiles\web\package.json
#      - dependencies["dsh-services-manager"] = "link:G:/Projects/dsh-plugins/dsh-services-manager"
#      - dsh.profile.bundles 里出现 "dsh-services-manager"
Select-String -Path "$env:USERPROFILE\.dsh\profiles\web\package.json" -Pattern "dsh-services-manager"

# 3) 前置条件：该 profile 的 cordis.patch.yml 必须给 connection 行注入 webServer
Select-String -Path "$env:USERPROFILE\.dsh\profiles\web\cordis.patch.yml" -Pattern "id: connection" -Context 0,3
#    期望看到：
#    - id: connection
#      inject:
#        - webRuntime
#        - webServer
#    本机正式的 web profile 已有；新建的 profile（例如沙箱）必须自己补，否则插件加载即失败：
#    cannot get property "webServer" without inject —— 整个 profile 树都起不来。

# 4) 重启 dsh（composition / bundle patch / 客户端 bundle 只在进程启动时加载）
#    用 dsh-restart skill（需先取得用户对这一次重启的明确同意）；重启后页面需要新实例的 token URL。
```

## 安装后验证清单

1. 打开 **设置**，左侧导航出现「服务管理」（齿轮图标；`order:50`，排在 General / Claw Kit / 任务视图之后）。
2. 分区内状态与本机实测一致，可对照：

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 3080,4319,5173 |
  Select-Object LocalPort,OwningProcess
```

期望：内置 `dsh` 条目 = 本实例（`managed: false`）；mechanics / tiny-world 若由别人启动则显示
`discovered`（所有权不是本插件），PID 与上表一致。
3. 打开一次「配置 (JSON)」，确认路径是 `<DSH_HOME>\.dsh-services-manager\services.json`，且首次运行已写入默认内容。

## 回滚

```powershell
# 1) 从 profile 移除（会同时删掉依赖与 bundles 行）
dsh plugin --profile web remove dsh-services-manager
Select-String -Path "$env:USERPROFILE\.dsh\profiles\web\package.json" -Pattern "dsh-services-manager"   # 应无输出

# 2) 重启 dsh，分区消失

# 3) 可选：删除插件状态（配置与日志）。删掉即丢失你添加的服务定义。
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\.dsh-services-manager"
```

只停用、不删包：把 bundles 行注释掉或把依赖留着不加载，然后重启。
若只想让某条服务不再被管：在面板里编辑配置、把该条目从 `services` 数组里删掉并保存，这不会动任何正在运行的进程。

## 故障排查

| 现象 | 检查 |
| --- | --- |
| 设置页没有「服务管理」 | profile 的 `dsh.profile.bundles` 是否有该包名；`node_modules/dsh-services-manager` 是否是指向仓库的链接；重启日志里有没有 `plugin tree failed to load` |
| 整个 profile 起不来，日志 `cannot get property "webServer" without inject` | 该 profile 的 `cordis.patch.yml` 缺 `connection` 行的 `webRuntime`/`webServer` 注入（见安装第 3 步） |
| 整个 profile 起不来，日志 `cannot get property "config" without inject` | 宿主半边误用了 `ctx.config`；插件体必须用 `apply(ctx, config)` 的第二个参数 |
| 分区出现但一直报错 | 宿主日志里搜 `[dsh-services-manager]`；RPC 通道是 `/dsh-services`（缺 `connection` 服务时不会注册） |
| 服务显示 `discovered` 而不是 `spawned` | 正常：这条服务不是本插件启动的（例如手工起的 vite / mechanics）。重启它会先做签名校验 |
| 重启被拒 `PORT_OWNED_BY_OTHER` | 端口占用者的命令行与 `match.commandLinePattern` 不匹配。确认那是你的服务后，用面板的强制接管（或在配置里把该条设为 `takeover: "force"`） |
| 保存配置报 `CONFIG_CONFLICT` | 文件被外部改过。点「重新载入」拿最新内容再改 |
| 一键重启 dsh 后页面打不开 | 新实例的 token URL 在 `%USERPROFILE%\.dsh\.dsh-services-manager\logs\dsh-web.log` 最后一行；重启过程记录在同目录 `host-restart.log` |

## 日志位置

| 文件 | 内容 |
| --- | --- |
| `<DSH_HOME>\.dsh-services-manager\logs\host-restart.log` | dsh 自我重启的每一步（`requested:` / `restart:` / `cleanup:` / `started pid`） |
| `<DSH_HOME>\.dsh-services-manager\logs\dsh-web.log` | 重启后新实例自己的 stdout/stderr（含 token URL） |
| 面板每行的「日志」 | 由本插件启动的服务的 collected 输出（内存 tail + spill 文件） |

## 沙箱安装（开发时用，不动正式 profile）

```powershell
$sandbox = "G:\Projects\dsh-plugins\dsh-services-manager\.sandbox\dsh-home"
$env:DSH_HOME = $sandbox
New-Item -ItemType Directory -Force $sandbox | Out-Null
dsh --profile sandbox --from-default-profile web --dump-config     # 建独立 profile
# 写入 $sandbox\profiles\sandbox\cordis.patch.yml 的 connection 注入（见安装第 3 步）
dsh plugin --profile sandbox add G:/Projects/dsh-plugins/dsh-services-manager
dsh --profile sandbox --port 3099 --no-open *> "$sandbox\..\logs\sandbox-web.log"
```

通过标准见 `AGENTS.md`。用完记得停掉 3099。
